# Content area

This document defines the minimal content area for the two supported application views: overview and manual annotations. It intentionally defers detailed page layouts and individual widgets.

## 3.1 Content sketch

```text
+--------------------------------------------------------------------------+
|   [Incremental refresh]  [Full refresh from source]                       |
| [3.1] Overview configuration                                             |
|   - date range                                                            |
|   - time aggregation                                                      |
+--------------------------------------------------------------------------+
| [3.2] Metrics                                                            |
|   - Overview KPIs                                                         |
|       - total input tokens                                                |
|       - total output tokens                                               |
|       - other summary indicators                                          |
|   - Token consumption over time                                           |
|   - Total token consumption                                               |
+--------------------------------------------------------------------------+
```

This conceptual layout corresponds to the main content region in [000-main-layout.md](./000-main-layout.md) (`0.3`).

## 3.2 Content responsibilities

### 3.2.1 View Parameters / View Configuration

Show **Incremental refresh** and **Full refresh from source** side by side in a single row immediately above the **Overview configuration** heading. Under the heading, show **Date range** and **Time aggregation**. Time aggregation offers hourly, daily, weekly, and monthly buckets. Overview results use the date range and the [sidebar filters](./010-navigation.md#15-filters).

**Incremental refresh** loads new records and retains imported history. **Full refresh from source** replaces the imported dataset with the source records currently available. Explain beside the full refresh action that previously imported history can disappear and that saved markers and agent names are kept. See [source collection](../02-architecture/02-design/000-system-overview.md#component-behavior).

#### Date range

Show a **Date range** selector in Overview configuration. Resolve the presets against the app's local date each time Overview renders. In the option list and the selected value, show each bounded preset's name followed by its inclusive dates in `YYYY-MM-DD` format. **Today** shows one date, and **All Time** shows its name alone. Reports use the same bounds shown in the selector.

| Preset | Date limits |
| --- | --- |
| **Today** (default) | Today's date |
| **All Time** | Unbounded |
| **Current week** | This week's Monday through today |
| **Last week** | Last week's Monday through Sunday |
| **Current month** | This month's first day through today |
| **Last month** | Last month's first through last day |

### 3.2.2 Metrics

The second block displays summary metrics and trend visualizations.

#### 3.2.2.1 Overview KPIs

Show these KPIs for each reporting window with one short explanation on each metric. Show the agent count alongside the KPIs. Distinguish observed facts, manual annotations, and estimates. Use [token accounting and rate rules](../02-architecture/02-design/020-backend-class-design.md#token-accounting) for coverage and unavailable values.

| KPI | Explanation |
| --- | --- |
| Total tokens | Sum of recorded total tokens for input and output. |
| Input tokens | Tokens sent to the model, including cached input. |
| Output tokens | Tokens generated by the model, including reasoning tokens when reported as output. |
| Cache percentage | Share of input served from cache where both input counts are known. |
| Daily average | Total tokens divided by the reporting window's duration in days. |
| Cached input | Input tokens reused from cache. |
| Non-cached input | Input minus cached input where both counts are known. |

#### 3.2.2.2 Trends and charts

Below the KPIs for each reporting window, show seven charts in these two sections, in order.

| Section | Chart | Grouping |
| --- | --- | --- |
| Token consumption over time | Project over time | Project and time bucket |
| | Agent over time | Agent and time bucket |
| | Agent by project over time | Project, agent, and time bucket, with agents grouped visibly by project |
| | Model over time | Model and time bucket |
| Total token consumption | By model | Model across the window |
| | By project | Project across the window |
| | By agent | Agent across the window |

All seven charts use the same filtered usage and display total tokens. The trend charts use the selected time aggregation and show buckets from oldest to newest by recorded clock time. An unknown bucket appears after dated buckets when present. The three summaries aggregate the entire reporting window and keep the same totals when time aggregation changes. Show a readable unknown attribution label where applicable and distinguish unknown token counts from zero.

Group agent charts by reporting name. Use the user-assigned name if present, otherwise the recorded name, then the recorded role, then **Default**. The [sidebar Agent filter](./010-navigation.md#15-filters) uses the same reporting name.

Use an empty state for a chart without plottable totals and retain the reporting window's empty-range state. The **Download usage CSV** action includes the scope summary and all seven breakdowns for each reporting window. Within each trend breakdown, order rows by time bucket and then group names. Within each summary breakdown, order rows by group name.

#### Saved time markers

Users can create, rename, edit, and delete named timestamps. Markers have no chat criterion, apply across chats, and persist across restarts and rebuilds.

#### Reporting windows

Filter by inclusive recorded calendar date, group using recorded clock labels (with weeks starting Monday), and display recorded timestamps and offsets. Compare marker instants using their offsets. When mixed offsets do not establish a single elapsed duration, leave the corresponding rate unknown.

Show **Full selected period** and, when a marker is selected, **Since [marker name]** together. The latter is the intersection of the selected range and the time starting at the marker, inclusive. Apply the same filters across chats to both. The marker adds only the inclusive cutoff. Show the marker timestamp and effective bounds, and display **No time in range** for an empty intersection. Use the [token accounting rules](../02-architecture/02-design/020-backend-class-design.md#token-accounting) for coverage and rates.

## 3.3 Content behavior

### 3.3.1 Parameter-driven updates

Metrics and charts update according to the Overview date range, sidebar filters, and applicable view configuration. If source refresh fails, show a diagnostic and keep displaying the last committed results.

### 3.3.2 Scope boundaries

This document intentionally does not define:

- exact field layout within the configuration block
- exact chart types where unspecified
- a separate manual-annotations management surface

The spec remains minimal until a later UI pass adds page-specific details.

## 3.4 Unresolved details

The current scope does not confirm:

- whether the configuration block is collapsible or always visible

These are intentionally deferred.
